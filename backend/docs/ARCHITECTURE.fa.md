# معماری فروشگاه

این پروژه یک **Modular Monolith** است: استقرار ساده‌ی Laravel را نگه می‌دارد، ولی مرزهای دامنه روشن‌اند. قراردادهای بیرونی در `app/Contracts`، پیاده‌سازی درگاه‌ها در `app/Services`، مدل داده در `app/Models` و ورودی HTTP در `app/Http` قرار دارد. در گام بعد هر دامنه به `app/Modules/<Module>` منتقل می‌شود، بدون آن‌که قرارداد API تغییر کند.

## تصمیم‌های اصلی

- مبلغ‌ها همگی عدد صحیح و برحسب تومان ذخیره می‌شوند؛ تبدیل ریال زرین‌پال فقط داخل adapter انجام می‌شود.
- محصول از واریانت جداست. رنگ، سایز، جنس یا هر ویژگی آینده داخل `attributes` و `product_variants.attributes` قرار می‌گیرد؛ بنابراین فروشگاه صنایع دستی و لباس یک هسته دارند.
- OTP یک‌بارمصرف، هش‌شده، دو دقیقه‌ای، دارای محدودیت تلاش و rate limit است. در محیط توسعه کد `12345` و پیامک در log نوشته می‌شود.
- مدیر نوع جداگانه‌ای از کاربر نیست؛ کاربر دارای Role است. این طراحی جلوی دو حساب موازی برای یک موبایل را می‌گیرد.
- درگاه پرداخت و پیامک با Strategy/Adapter و قراردادهای `PaymentGateway` و `SmsGateway` تعویض می‌شوند.
- تنظیمات کلیدی/گروهی‌اند؛ برند، رنگ، لوگو و صفحات ثابت بدون تغییر کد قابل جایگزینی هستند.

## ماژول‌ها

Identity (کاربر، مدیر، نقش، OTP)، Catalog (محصول، تنوع، دسته، برند، رسانه و تاریخچه قیمت)، Sales (سفارش، تخفیف، پرداخت)، Fulfillment (آدرس، روش و بازه ارسال)، Content (اسلایدر، بنر، FAQ، مقاله و دیدگاه)، Engagement (علاقه‌مندی و ذخیره مقاله) و Settings.

## اجرای محلی

```bash
composer install
copy .env.example .env
php artisan key:generate
php artisan migrate --seed
php artisan serve
```

مدیر نمونه: `09120000000` — کد OTP توسعه: `12345`.
